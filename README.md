# Моя доступность — рабочий прототип

## Что это

Общий веб-календарь, в котором один человек редактирует доступность, а коллеги видят изменения.

Статусы:
- 🟢 Доступна
- 🟡 Занята, но если жесть как надо, готова
- 🔴 Совсем не могу
- ⚪ Не работаю
- 🟠 Сверхурочно
- 🔵 Отгул за сверхурочное

Есть также количество сверхурочных часов и комментарий.

## Архитектура

React + Vite → Supabase Postgres → Supabase Realtime.

Данные хранятся в облаке, поэтому коллеги открывают одну и ту же опубликованную ссылку.
Realtime сообщает уже открытым страницам об изменениях.

## Запуск локально

1. Установить Node.js.
2. В терминале:
   npm install
3. Создать проект в Supabase.
4. В Supabase -> SQL Editor выполнить `supabase.sql`.
5. Скопировать `.env.example` в `.env.local`.
6. Заполнить:
   VITE_SUPABASE_URL=...
   VITE_SUPABASE_PUBLISHABLE_KEY=...
7. Запустить:
   npm run dev

## Публикация общей ссылки

Самый простой вариант — Vercel:

1. Создать репозиторий GitHub и загрузить этот проект.
2. В Vercel выбрать Import Project и этот репозиторий.
3. В Environment Variables добавить:
   VITE_SUPABASE_URL
   VITE_SUPABASE_PUBLISHABLE_KEY
4. Deploy.
5. Vercel выдаст ссылку вида `https://...vercel.app`.
6. Именно эту ссылку отправить коллегам.

## ВАЖНО: защита редактирования

В этом прототипе политика записи открыта, чтобы проект можно было сразу проверить.

Перед реальным использованием нужно сделать авторизацию владельца:
- коллегам оставить `SELECT`;
- тебе дать `INSERT/UPDATE`;
- убрать анонимные `INSERT/UPDATE`.

Supabase поддерживает Auth и Row Level Security для такого сценария.
